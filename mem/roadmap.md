## Fase 4 — Relatórios avançados + IA
30. ✅ Warehouse + Report Builder + Anomaly Detection — schema OLAP-lite (`dim_date`, `fact_tasks_daily`, `fact_posts_daily`) populado pela RPC `refresh_warehouse(tenant)` que reagrupa últimos 90d de tarefas (squad/projeto/assignee/tipo) e posts (canal/campanha). `saved_reports` (source tasks|posts, métricas/dimensões/filtros como JSONB, chart_type bar|line|pie|table, favoritos) + `report_schedules` (cadência+recipients+next_run). RPC `run_report` monta SQL dinâmico com whitelist rígida de colunas e devolve linhas+chart_type. `metric_anomalies` (severity info|warning|critical, expected/observed/delta_pct, status open|ack|dismissed) alimentada pela RPC `detect_anomalies` que compara últimos 7d vs média de 30d em done_count, overdue_count e engajamento social. Edge functions: `refresh-warehouse` (rebuild por tenant) e `detect-anomalies` (roda RPC + IA Gemini Flash escreve `explanation` curta acionável em PT-BR para cada anomalia aberta). Páginas: `/app/reports` (3 colunas — lista de salvos / builder com source+gráfico+filtros de data + chips de métricas e dimensões / preview ao vivo bar/line/pie/table com recharts e botão Atualizar warehouse) e `/app/anomalias` (3 abas open/ack/dismissed, cards coloridos por severidade com setinha down/up, badge de delta, bloco IA destacado, ações Reconhecer/Dispensar). Sidebar Insights ganha "Report Builder" e "Anomalias IA".
31. ✅ Forecast + OKRs + agendamento de relatórios — Tabelas `goals` (período + status active/at_risk/done/dropped) e `key_results` (source tasks|posts|manual, baseline/target/current_value, direction up|down). RPC `kr_progress(tenant)` puxa current_value de cada KR direto do warehouse (`fact_tasks_daily`/`fact_posts_daily`) e marca goal como `at_risk` se progresso médio < 50% após meio do período. RPC `forecast_metric(tenant, source, metric, days_back, days_ahead)` faz regressão linear simples no histórico do warehouse e devolve série combinada (history + forecast). RPCs `compute_next_run(cadence)` e `due_schedules()` para a fila de envios. Edge functions: `forecast-metric` (roda RPC + Gemini Flash gera narrativa curta em PT-BR explicando tendência) e `send-scheduled-reports` (varre `due_schedules`, executa `run_report`, monta HTML com tabela e envia via Resend para os recipients quando `RESEND_API_KEY` presente — modo dry-run sem). Páginas: `/app/forecast` (seleciona fonte+métrica, gráfico LineChart com linha sólida histórica e tracejada de previsão, ReferenceLine "hoje", 3 KPIs de média histórica/prevista/tendência, card IA com narrativa) e `/app/okrs` (lista de goals com progresso médio e badge de status, expansão mostra KRs com Progress bars individuais, dialog de criação de goal e KR com presets de métricas do warehouse, KRs manuais editáveis inline, botão "Recalcular progresso" chama `kr_progress`). Bloco "Envio agendado por email" embutido no Report Builder permite criar/listar/excluir agendamentos por relatório e botão "Processar fila agora". Sidebar Insights ganha "Forecast IA" e "Goals & OKRs".
32. ✅ Notificações smart + crons + Executive dashboard — Schema `notifications` (kind enum, severity, link, payload, read_at, realtime habilitado), `notification_preferences` (digest off/daily/weekly, in_app, quiet hours, seed automático via trigger ao virar membro de tenant) e `notification_rules` (tenant+user+kind com channels in_app/email). RPC `scan_notifications(tenant)` cria alertas idempotentes para anomalias críticas/warning abertas (24h), goals em risco (7d) e tarefas com deadline em <24h — distribui para admins/managers ou direto pro assignee. RPC `mark_notifications_read(_ids)` marca lidas. RPC `exec_kpis(tenant)` agrega 10 KPIs executivos (done 7d, delta vs 7d anteriores, overdue de ontem, anomalias abertas, goals em risco, ROAS, receita, gasto, engajamento 7d). Edge functions: `scan-notifications` (varre todos os tenants ou um específico), `exec-briefing` (chama `exec_kpis` + Gemini Flash gera narrativa executiva PT-BR de 4 frases — destaque positivo + risco + ação) e `cron-tick` (orquestrador central que aceita job=warehouse|anomalies|krs|notifications|reports|all e encadeia RPCs/funções). Cinco jobs pg_cron agendados: warehouse 03:00 diário, anomalias hourly, krs 04:00 diário, notifications a cada 30min, reports a cada 5min. Páginas: `/app/notificacoes` (3 abas Não-lidas/Lidas/Preferências, cards coloridos por severidade com icon por kind, botão Atualizar e Marcar todas, switch in-app + select digest), `/app/automacoes` (5 cards de jobs com schedule + descrição + botão "Executar agora", botão "Rodar tudo") e `/app/exec` (Executive Dashboard com 6 KPI cards clicáveis com link contextual, card destacado de briefing IA com refresh, 2 cards complementares de tendência/funil social). Sidebar Insights ganha "Executive" no topo e Sistema ganha "Notificações" + "Automações".
33. ✅ Public API + webhooks + chat + PWA — Schema `api_tokens` (sha256 hash + scopes read/write + prefix visível + expires/revoked), `webhooks` (URL + events + secret hex 24b para HMAC + active toggle), `webhook_deliveries` (fila com status pending/sent/failed + http_status + attempts até 5 + response body), `chat_integrations` (provider slack|teams|discord + webhook_url + events) e `push_subscriptions` (endpoint+p256dh+auth por usuário+device). Página unificada `/app/developer` com 4 abas (API com criar/copiar/revogar tokens + endpoint base; Webhooks com criar/togglar/remover + lista de últimas 30 entregas com status; Chat com conectar Slack/Teams/Discord + botão testar; Mobile com botão de instalar PWA detectando beforeinstallprompt + ativar push notifications). 34. ✅ Copilot IA + Benchmarks setoriais + Simulações What-if — Fecha a Fase 4. Tabelas `copilot_conversations` + `copilot_messages` (histórico por usuário, role user/assistant/tool/system, tool_calls/tool_name/tool_result em JSONB), `industry_benchmarks` (14 seeds: default + agencia_marketing + ecommerce + saas_b2b com p25/p50/p75 para engagement_rate, reach_per_post, ctr_link_in_bio, roas, ontime_delivery, task_cycle_days, overdue_rate, approval_cycle_hours), `simulation_scenarios` (kind boost_budget|team_capacity|cadence_change|custom + inputs/result/ai_narrative), `monthly_scorecards` (period_month UNIQUE por tenant + metrics + benchmarks + ai_summary + recommendations JSONB). `tenants` ganha `industry` (default 'default').
